# gpxinput RDR2 扳机震动 mod

给《荒野大镖客 2》补上 PC 版从来没有的**扳机震动**。

- **类型**：hook（XInput 反向代理 DLL）
- **目标**：Red Dead Redemption 2 PC，1.0.1491.50（R* / Epic / Steam 版通用）
- **原理**：不注入、不改游戏代码、不改游戏数据。代理冒充 `xinput9_1_0.dll`
  被游戏加载，完整转发到系统原件，只在震动调用上做加工

---

## 0. 功能与依赖

| 功能 | 状态 | 需要状态组件？ |
|---|---|---|
| 开枪 → **四路脉冲**（左/右扳机 + 左/右握把），每把枪独立参数 | ✅ | 需要（没装则用通用参数） |
| 每把枪不同手感（已录入 **34 把**，其余按武器组） | ✅ | 需要 |
| 瞄准 → 左扳机持续微震 + 握把低频小起伏；**久瞄幅度加剧** | ✅ | 需要 |
| 拉弓 → 两侧扳机持续震动（随拉满增强）；松弦 → 发射脉冲 | ✅ | 需要 |
| 骑马 → **四条腿蹄音**：节奏随马速变快、幅度小幅增加；走路几乎无感 | ✅ | 需要 |
| 手柄没有扳机通道时自动折算到同侧体感 | ✅ | 不需要 |
| 四路**逐路直通**开关（某一路完全交还游戏原值） | ✅ | 不需要 |
| LT 按下反馈 / 装弹反馈 | 默认关闭，可开 | 装弹需要 |

**游戏内状态组件 `gpxinput_rdr2.asi`（可选但强烈建议装）**

它是「按武器分档 / 瞄准微震 / 拉弓震动 / 骑乘辅助」的前提：每帧读几个游戏 native
（当前武器、是否瞄准、是否开枪、是否装弹、是否骑马、马速），写进一块共享内存，
代理据此给手感。它**只读**游戏状态，不修改任何游戏行为。

- 需要 **ScriptHookRDR2**（绝大多数 RDR2 mod 环境已经装了）
- **不装也能用**：代理检测不到状态就退回通用参数，扳机脉冲照常，只是少了按武器分档那几项
- 删掉即无痕迹

## 1. 可用的两路，具体是什么手感

| 效果 | 说明 |
|---|---|
| **开枪 → 扳机脉冲** | 每打一发给一个脉冲：约 **170ms**、峰值打满。判据是「右扳机扣下」，由代理直接读手柄的扳机模拟量得到，不依赖任何游戏状态 —— 这也是目前唯一能用的判据 |
| **按下 LT → 左侧一下** | **按下去就震一下**（默认 110ms、0.70 强度，只走左侧，和开枪的右侧区分开）。按住不会持续震：按下去只震一次，松开再按才有第二下 |
| 手柄没有扳机电机也能用 | 扳机那两路的数值会按 `TrigToBody` 折算到同侧体感马达 —— 多数第三方手柄走这条，手感不丢但由体感表达 |
| 任何一路都能退回原生 | 四个电机各自一个开关（`Drive*`），设 `false` 的那一路游戏给什么就发什么 |
| 其余一切照旧 | 游戏原生震动原样保留，我们只是叠加 |

## 2. 安装

1. **关闭 Steam Input**
   Steam → 设置 → 控制器 → 对 Xbox 手柄停用 Steam 输入。
   它也会挂钩 XInput，两边同时挂钩行为不可预测。
2. 把这两个文件复制到 **RDR2 游戏根目录**（与 `RDR2.exe` 同级）：

   | 文件 | 必须 | 作用 |
   |---|---|---|
   | `xinput9_1_0.dll` | ✅ | 代理本体（RDR2 静态导入的就是这个名字） |
   | `gpxinput.ini` | ✅ | 全部开关与手感参数 |

3. 启动游戏（经 `Launcher.exe`）。**先不用管理员试**：
   扳机默认走 `Windows.Gaming.Input`，这条路不要管理员。只有退到 HID 输出报告
   那条路时才需要管理员（第 6 节第 1 条），日志里会写明用的哪条。

> `xinput1_4.dll` / `xinput1_3.dll` 是同一份代码给别的游戏用的，RDR2 用不到，可以不复制。

---

## 3. 怎么确认它在工作

游戏跑起来后，游戏目录里会出现代理日志 `xinput9_1_0.<pid>.log`：

```
gpreal: 真身已加载 -> C:\WINDOWS\system32\xinput9_1_0.dll     ← 代理生效
hooks: 2 个挂钩已启用                                          ← 挂钩成功
haptics: 自合成开启 开枪(扳机判据=开 扣下阈值=0.55 ...)          ← 参数已加载
wgi: 通道可用（手柄 1 个）—— 扳机走这条路，不需要管理员权限          ← 扳机的出口
engine: 输出通道=Windows.Gaming.Input(四电机) —— 四个电机全可控（含扳机）
gpreal: 转发 XInputSetState(...)                              ← 游戏在发震动
```

**最关键的是「输出通道=」那一行**：它写 `XInput(只有两个马达)` 时，扳机那两路
其实是发不出去的（内容会按 `TrigToBody` 折算到体感马达）—— 这时候「扳机不震」
是通道问题、不是参数问题，看日志就能分清。

把 `LogLevel` 改成 `debug`，还能看到每次开枪判定的细节。

## 4. 配置

`gpxinput.ini`，改完**重启游戏**生效。

### `[Proxy]` —— 行为开关

| 键 | 默认 | 说明 |
|---|---|---|
| `Mode` | `2` | 0=透传（只观察）1=改写 2=阻断替换。**改动感前先用 0 看数据** |
| `Triggers` | `true` | 是否驱动扳机（需要 HID + 管理员） |
| `Output` | `0` | 0=自动 1=只用 XInput（两个马达）2=只用 HID（四个电机） |
| `LogLevel` | `info` | 排查时改 `debug` |
| `MonitorAutoStart` | `false` | 设 `true` 会在启动游戏时弹出监视窗口（需要自备 `gp_monitor.exe`） |
| `CaptureFile` | 空 | 填路径则录制震动帧 CSV（源码树里的 `xinput_test.exe --replay` 可回放） |

### `[Haptics]` —— 合成参数

| 键 | 默认 | 说明 |
|---|---|---|
| `SelfHaptics` | `true` | 自合成总开关。关掉它这个 mod 就退化成「什么都不做」的代理 |
| `ShotFromTrigger` | `true` | 开枪判据：右扳机扣下 |
| `TriggerPressThresh` | `0.55` | 扣到多深算「扣下」。调小 → 更容易触发；调大 → 要扣得更实 |
| `TriggerReleaseHyst` | `0.20` | **相对**峰值的回弹量（连发必需，见第 6 节第 3 条） |
| `TriggerRefractoryMs` | `150` | 两次开枪判定的最小间隔 |
| `ShotGain` / `ShotEnvMs` | `2.0` / `170` | 开枪脉冲的强度与时长（当前生效的就是这两个值） |
| `ShotBodyKick` | `0.30` | 同一次开枪附加到体感马达的量。**手柄没有扳机电机时，这才是你真正摸到的那个量**，可以直接调到 0.6 甚至更高 |
| `LtPressGain` / `LtPressEnvMs` | `0.70` / `110` | 按下 LT 那一下的强度与时长（只走左侧） |
| `TrigToBody` | `0.45` | 没有扳机通道时，把扳机内容折算到同侧体感马达的比例 |
| `DriveLeftMotor`<br>`DriveRightMotor`<br>`DriveLeftTrigger`<br>`DriveRightTrigger` | `true` | **逐路直通**：设 `false` 的那一路完全由游戏原值决定，我们一点不碰（连扳机折算都不落上去）。想让体感保持原生、只让扳机动 → 两个 `Motor` 设 `false` |
| `RideEnable` | `false` | 骑乘辅助。**有状态组件时**判据是「在马上 + 马速」，按马速给节奏（走起来轻而慢、跑起来重而快，站着不动不给）——这条可靠；没有状态时退回波形判据，那条在 RDR2 上不可靠，所以才默认关闭 |
| `RideSpeedLow` / `RideSpeedHigh` | `1.0` / `9.0` | 马速（游戏单位/秒）映射区间：低于 Low 不给辅助，到 High 就是最快最重 |
| `RideMinPeriodMs` / `RideMaxPeriodMs` | `200` / `900` | 一拍的周期范围（毫秒），按马速在两者之间插值 |
| `UseGameState` | `false` | 采信游戏内状态组件。**本包不含该组件**，打开也没有效果 |

### `[Debug]` —— 调试模式（排查时才开）

打开后一次把排查要用的东西备齐：**自动拉起监视窗口和状态窗口**、日志提到 debug。
平时这些都是关着的（发布形态就是要安静），于是排查时经常出现「以为是没数据，
其实是窗口压根没开」。

两种打开方式，任选其一：

1. 在 ini 同目录放一个**空文件** `gpxinput_debug.on` —— 建文件=开、删文件=关，
   最快的开关，不用改配置；
2. 把 `[Debug]` 里的 `Mode` 改成 `true`。

文件优先：文件在就是开，文件不在才看 ini。

| 键 | 默认 | 说明 |
|---|---|---|
| `Mode` | `false` | 调试模式总开关 |
| `Monitor` | `true` | 调试模式下拉起 `gp_monitor.exe`（四电机实时监视） |
| `StateView` | `true` | 调试模式下拉起 `gp_state_view.exe`（武器组名字 / 动作 / 马速） |
| `VerboseLog` | `true` | 日志级别自动提到 debug（`[Proxy] LogLevel` 写得更高就不动它） |
| `ToolDir` | 空 | 工具所在目录。留空 = 游戏目录。**想保持游戏目录干净就把工具放别处，这里写那个目录** |

> 这两个窗口是独立的控制台进程，工具不存在就跳过并记一条日志，崩了、被你关了
> 都不影响手柄链路。**它们不在发布包里**（属于开发工具），需要时从源码
> `build/tools/` 里取。

### `[Weapon0]`..`[Weapon7]` —— 不同枪不同手感

**当前不生效**：这 8 档参数需要游戏内状态组件才能分得清武器，本包不含该组件。
留在配置里是为了组件做完之后可以直接用，现在改它们不会有任何变化。

每档的旋钮：`ShotGain`（强度）、`ShotEnvMs`（时长）、`ShotBodyKick`（体感附加量）、
`AimTrig` / `AimBody` / `AimWobble`（瞄准时用，同样未生效）。

## 5. 卸载

删掉游戏目录里的 `xinput9_1_0.dll`、`gpxinput.ini`（以及日志与 CSV）即可。

这个 mod **不写游戏文件、不改注册表、不 hook 游戏代码**，删掉即完全还原，
存档与其它 mod 不受影响。

## 6. 已知限制

1. **驱动扳机有两条路，能不能用取决于手柄和连接方式。**
   - `Windows.Gaming.Input`（默认首选）：走手柄驱动栈，原生含左右扳机，
     **不需要管理员**，而且跟「设备是否暴露 HID 输出报告」无关 ——
     网页版手柄测试（gpadtester 之类）用的就是这条，它震就说明这条路通。
   - `HID 输出报告`：需要设备暴露可写的 9 字节报告 + 管理员权限。很多手柄
     （第三方、部分无线连接）不暴露，日志里会写「枚举到 0 个可用的 HID 输出接口」。
   - 两条都不可用时自动退回两个体感马达，把扳机内容折算过去（`TrigToBody`），
     手感不丢但由体感表达。**这时日志的「输出通道=」那行写的是 XInput。**
2. **「扳机判据」本身有固有局限。** RDR2 里 RT 不只在开枪时扣（菜单、交互、
   骑马催马都可能扣到阈值），这些场合也会给一下脉冲。这是判据的局限、不是 bug，
   要彻底解决只能靠读游戏状态（未完成的那部分）。
3. **RDR2 的震动波形里没有事件信息。** 实测它的 PC 震动是一条连续渐变
   （两路之和恒为 255，约 2 秒走完全程），开枪、骑马、撞车在波形上完全分不出来。
   所以「不同枪不同手感」「只有真开枪才给脉冲」这些事不可能靠分析波形做到 ——
   这也是为什么那些功能需要状态组件。
4. **「开了几枪之后一直震」的两个成因**（都已修掉，记在这里以免重复踩）：
   - 模拟扳机在阈值附近抖动 → 一次扣下被算成连续多次。现在用**相对峰值的
     回弹**（`TriggerReleaseHyst`）复位：持续按住只给一个脉冲，松一半再扣
     算一次新的。
   - **手柄会一直保持最后收到的震动值**，所以「不再发新值」不等于「停止震动」。
     引擎在「没有游戏值、也没有合成内容」时会显式补一帧全零刹车。

## 8. 从源码构建

```bash
xmake f -p windows -a x64 -m release
xmake
```

产物：

| 产物 | 说明 |
|---|---|
| `build/proxy/xinput9_1_0/xinput9_1_0.dll` | 发布包里的代理（另有 `xinput1_3` / `xinput1_4` 两个同名变体） |
| `build/bin/gpxinput_rdr2.asi` | 游戏内状态组件（**未完成，不发包**） |
| `build/bin/gp_monitor.exe` | 监视窗口（开发用） |
| `build/tools/gp_envtest.exe` | 离线量脉冲包络（开发用） |
| `build/tools/shresolve_test.exe` | 验证能否从 `ScriptHookRDR2.dll` 取到脚本入口（开发用） |
| `build/tools/xinput_test.exe` | 回放录制的震动帧（开发用） |

打包：`python tools/package_rdr2.py`（把 `build/` 里的产物刷新进
`dist/rdr2_haptics/` 并打出 zip）。
